# 剧本播放验证记录

> 对外版。以下结果整理自 2026-11-11 的既有验证记录，本次文档发布未重新执行这些实机测试。测试剧本不随公开仓库发布，本文不提供素材下载。

验证日期：2026-11-11。目标是使用客户电脑上的本地动作 CSV 和同名 MP3 播放，不向机器人复制剧本文件。

## 验证环境

- Ubuntu 22.04 x86_64 虚拟机，本机 GCC，桥接有线网卡 `ens33`，本机地址 `192.168.110.129`。
- 机器人地址 `192.168.110.51`，SDK 连接 DDS Bridge 对外域 `50`。
- 输入为内部测试用 CSV 与同名 MP3。测试素材不对外提供，也不包含在公开仓库中；客户需自行准备符合公开格式的文件。

## 部署、构建和格式检查

- `scripts/deploy_ubuntu.sh` 完整依赖安装及部署执行成功；脚本检测到 `ens33 / 192.168.110.129`、机器人路由和 GStreamer 所需插件，并完成本机 GCC 构建及动态库检查。
- 使用 `gcc -Wall -Werror -pthread` 完整编译并链接 SDK，依赖 CycloneDDS 11.0.1 和 GStreamer App 库。
- 样例 CSV 严格加载为 17,245 帧，动作时间轴长度约 287.400 秒。MP3 解码为 9,251,944 字节、16 kHz 单声道 S16LE PCM，时长约 289.123 秒。
- ASan/UBSan 离线检查通过。样例接受；重复列、缺列、空字段、NaN、范围错误、时间戳错误及旧格式均拒绝。

## 机器人播放结果

- 在机器人启动、外部 DDS 域匹配且动作源空闲时完成全程播放。机器人仲裁日志记录 SDK 动作源 `aheadform_sdk` 获取控制权并在发送结束后超时释放；机器人网络侧收到连续 RTP 音频包。
- 播放结果为成功：17,245/17,245 个动作帧和 14,457/14,457 个 20 ms PCM 帧均由 SDK 发送，任务状态为 COMPLETED。
- 首帧 PCM 提交至扬声器发送管线后，SDK 记录单调时钟起点；首帧动作 DDS 发布完成时记录的间隔为 **150.325 ms**，符合设置的 150 ms 起播延迟。
- 该间隔是 SDK 发送调度的测量值。没有用声学设备或机器人关节传感器测量实际声压起点与机械运动起点，因此不能据此声称实体输出达到 150 ms 精度。网络、机器人缓冲、驱动和机械响应仍会引入偏差。
- 测试期间 CSV 和 MP3 保留在 SDK 电脑上，未复制到机器人；未修改机器人代码或配置。

## 限制与操作提示

- SDK 发送成功不代表机器人仲裁一定接受，也不代表动作已物理完成。播放前检查最新硬件状态、动作源和脸部/脖子运动许可。状态尚无新样本时等待下一帧后再查询。
- `OperatingMode 1` 曾出现请求超时，不能将其当作切换成功；本次验证没有把它作为播放前置条件。
- 完整自然结束已验证。单独停止测试在播放约 0.65 秒后调用 `StopScript`，命令成功并返回 STOPPED，子进程退出码为 0。该命令停止本地后续发送，已进入机器人缓冲的数据及动作源释放仍按机器人既有机制处理。

客户操作与文件格式见 [SDK 剧本播放快速上手](SDK剧本播放快速上手.md)；模块与能力边界见 [需求与总体架构设计](AheadFormSDK需求与总体架构设计.md)。
